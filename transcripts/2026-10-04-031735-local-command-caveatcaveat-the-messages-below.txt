     state file's cached model_id — still claude-fable-5-1 from before the

     you on sonnet while swearing you were on fable, and this very turn (now
     actually sonnet) shows asked=claude-fable-5-1 for session b1d69112 even
     though the real model already changed — the field is lagging by exactly one
     render cycle.
  2. The required-model mismatch is self-inflicted, not a bug in the hook's 
     logic. resolve_required() reads ~/.claude/settings.json's model key as the
     pin. But /model <x> writes that same key ("saved as your default for new
     sessions" — that's literally ~/.claude/settings.json). So every time you
     run /model, you move the goalpost the gate is checking against, for every
     repo with no project-level override. This repo (iphs400-mp2-cms-starter)
     has no .claude/settings.json or .claude/settings.local.json model key, so
     it always inherits whatever the global default currently is — which is
     exactly the race you hit: three /model calls in a row, each rewriting the
     global pin, while the gate kept re-checking against a moving target and a
     stale cached reading.
